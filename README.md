# Market Primer

A calm, daily explainer of the Indian stock market for someone with zero financial knowledge. Every weekday evening a Claude Code routine researches the day's market news, writes a new briefing, checks it and publishes it. The website is a single static page on GitHub Pages that reads those briefings.

- **Live site:** https://samikkodoth.github.io/market-primer/
- **Repository:** https://github.com/Samikkodoth/market-primer
- **Not financial advice.** Everything here is written automatically, for learning only.

## What each file does

| Path | What it's for |
|---|---|
| `index.html` | The whole website: layout, styles and code in one file. No build step. |
| `briefings/YYYY-MM-DD.json` | One briefing per trading day (India time). |
| `briefings/index.json` | The list of briefings. **Generated by `scripts/validate.py`, never edit by hand.** |
| `lessons/lessons.json` | The 13-lesson Basics course outline. |
| `lessons/<id>.txt` | One lesson each, as Markdown text. The `.txt` extension stops GitHub Pages from turning it into HTML. |
| `scripts/validate.py` | Checks every briefing against the data contract, then rebuilds `briefings/index.json`. Python standard library only. |
| `automation/daily-briefing.md` | The step-by-step procedure the routine follows every day. **Edit this to change the briefing style.** |
| `ROUTINE_PROMPT.md` | The short prompt stored in the routine. It points at `automation/daily-briefing.md`. |
| `CLAUDE.md` | Short project notes for any future Claude Code session. |

## How the daily flow works

1. At **18:30 IST on weekdays**, the routine "Market Primer daily briefing" starts a cloud Claude Code session on this repository.
2. It follows `automation/daily-briefing.md`. It checks the date and skips weekends, holidays and days that already have a briefing. Then it runs at least 10 web searches, writes `briefings/<today>.json`, and adds one missing Basics lesson if there is one.
3. It runs `python3 scripts/validate.py` until it prints `OK`, then commits and pushes to `main`.
4. GitHub Pages redeploys automatically within a minute or two. The site always loads the newest briefing listed in `briefings/index.json`.

### How the question buttons work (no API keys, no extra cost)

- **Explain like I'm 12** and **Real-life example** show answers the routine wrote in advance. They appear instantly, with no network call.
- **Explain more** on a highlighted word also shows pre-written text.
- **What about my SIP?**, **Has this happened before?**, the typed question box and **Learn it with Claude now** open `claude.ai/new` in a new tab with the question already filled in, so you just press send. This uses your normal Claude subscription. If your browser blocks the new tab, the question is copied to your clipboard instead.
- The site never calls any AI API, and there are no keys or secrets in this repository.

### Your progress

Your streak, saved words, quiz scores and finished lessons are kept in your browser's local storage. They stay on that device and browser only, and clearing site data erases them.

## Changing things later

- **Briefing style or content:** edit `automation/daily-briefing.md` on GitHub and commit. The routine reads it fresh on every run.
- **Run time:** change the schedule at [claude.ai/code/routines](https://claude.ai/code/routines).
- **Site design:** edit `index.html`. To test locally, run `python3 -m http.server` in the repo folder and open http://localhost:8000.
- **Before any commit that touches briefings:** run `python3 scripts/validate.py`.

## Troubleshooting

**No new briefing today**
- Weekends and market holidays have no briefing. That's expected.
- Open [claude.ai/code/routines](https://claude.ai/code/routines), open the routine and read the latest run's transcript. A green status only means the run finished. Check the end of the transcript to see whether it committed a briefing or stopped (for example, "market was closed").
- Routines count against your plan's usage and daily run limits. If you hit a limit, the run may not start.
- Check that the routine still has access to this GitHub repository.

**The routine's push was rejected**
- The transcript will say it pushed to a `claude/briefing-<date>` branch instead. Merge that branch into `main` on GitHub (open a pull request and merge it) and the site will update.
- To prevent it happening again, make sure `main` has no branch protection that blocks pushes, and that the routine has "unrestricted branch pushes" (or equivalent) enabled for this repository.

**The site doesn't load or shows "couldn't be loaded"**
- Right after setup, GitHub Pages can take a few minutes to publish. Refresh after a minute.
- In the repository, go to **Settings → Pages** and check the source is **Deploy from a branch → `main` / root**.
- Check the **Actions** tab for a failed "pages build and deployment" run.
- If the site shows an old day, do a hard refresh. The page asks for the newest list every time, but a phone browser may hold on to an old copy of the page itself.

**Something in a briefing looks wrong**
- Check the Sources list at the bottom of that day's briefing. Figures are copied from the day's reports and may later be revised.
- To fix a mistake, edit that day's `briefings/<date>.json` on GitHub, run the validator locally if you can, and commit. Don't edit `briefings/index.json`. The validator regenerates it, and the routine runs it on every future run anyway.
- If the style drifts, tighten the rules in `automation/daily-briefing.md`.
